# Feature request: approval workflow with audit trail

*From: Customer Operations. The business ask, in plain language. Run B uses this as the "Product" part of its description. Run A does not see it.*

Today, agents can **file** compensation claims for passengers after a disrupted flight, but
nothing decides them. A claim sits in "filed" forever.

We need claims to go through **approval**:

1. A claim that has been filed should be able to be **approved** or **rejected** by a member of staff.
2. Rejections need to say **why**.
3. We must be able to see the **history** of every claim: each decision, who made it, and when.
4. Supervisors and managers should be able to **view** that history. Agents should not.
5. Leadership needs to answer an auditor's question, "who approved what, when, and on what basis?", months later, and trust that the answer has not been altered.

Out of scope: emails or notifications, a user interface, reversing a decision.

You do **not** need to decide the approval limits or who may approve what. Those are set by
Customer Operations policy.
